# Design

## Context

仓库已有 WXT + Vue 3 模板。`entrypoints/popup` 目前展示示例组件，`entrypoints/content.ts` 和 `entrypoints/background.ts` 是模板入口。工作台在扩展自身的标签页运行，可复用 WXT 的 HTML 入口和扩展资源打包机制。

## Goals / Non-Goals

**Goals**

- 独立控制计算资源和界面渲染开销，取消操作后可继续使用原有输入。
- 用同一份完整文档来生成预览、定位搜索结果和下载文件，避免预览截断影响数据完整性。
- 以浏览器端到端实测衡量交互响应、任务耗时和内存开销。

**Non-Goals**

- 首版范围限于用户主动打开的扩展工作台、严格 JSON、字面搜索和行级差异。自动接管网页 JSON、正则搜索和结构化差异均留给后续变更。

## Decisions

### 工作台入口与文档归属

使用 WXT 独立 HTML 入口和 Vue 页面，通过扩展图标直接打开标签页。短时弹窗适合简单操作，独立页面给双栏和大文档任务提供稳定的生命周期与显示空间。清理模板的弹窗和内容脚本，减少扩展的页面访问面。扩展后台仅负责入口，页面创建同源 Dedicated Web Worker，脚本和依赖随扩展打包。

页面为每份输入或结果保存文档 ID、版本和完整内容引用。小文档可以是文本，大文档优先使用 `File` 或 `Blob`，由 Worker 解码和计算。Worker 返回有界预览、状态、错误位置和可供导出或后续搜索使用的完整 `Blob`。文档更新时递增版本，转换、比较和搜索都携带请求 ID 和相关版本。页面仅接收匹配当前请求与文档版本的响应。

### 可取消计算和预算

重操作由页面对应的 Worker 执行。同步转换或 Diff 无法在计算过程中处理取消消息时，终止执行该任务的 Worker，下次操作按需重建。页面仍持有输入及已完成文档的引用。全文搜索使用独立的 Worker，并按有限工作量分段搜索，使切换关键词、导航和取消能够及时响应。文档版本改变时停止关联任务并释放旧结果。输入字节数、输出大小、嵌套深度、索引大小和 Diff 工作量在累计增长时检查。下载引用在使用结束后释放。

### 无损转换

格式化和压缩都按原文 token 范围写出结果，只处理字符串外的空白。优先评估 `jsonc-parser` 的扫描器和错误位置支持。严格语法校验覆盖注释、尾逗号、未转义控制字符、非法数字与额外顶层内容。扫描器的返回值经语法验证，输出引用原始片段。采用迭代状态栈处理嵌套并在输出增长时计量体积。`JSON.parse` 和 `JSON.stringify` 的对象往返会改变大整数、重复键或字面量形式，在该路径使用原文写出可以保留这些信息。字符串转义与反转义可使用原生 JSON 字符串 API，在涉及大输入时仍受文档预算约束。

### 预览、Diff 和全文搜索

小文档使用 CodeMirror 6 的可视区渲染。大文档显示带原文位置的有限片段，按需请求其他片段。文件大小、行数和最长单行共同决定显示模式，压缩后的超长单行也进入有界预览。Vue 状态保存文档版本、视图位置和统计信息。避免在响应式更新里重复读取全文、逐行创建组件或展开整棵 JSON 树。

Worker 将两侧校验并统一为两空格缩进，再用 `jsdiff` 生成行级差异。使用库的时间和编辑距离限制，并给包括预处理和序列化在内的请求设置整体看门狗。成功时保存左右行区间、差异导航信息及完整统一差异。界面按当前可见片段绘制高亮。预算用完时保留两侧输入和搜索，展示本次中止状态。选择行级比较使视图、导航和 `.diff` 共享同一语义。

搜索目标是当前选定侧的完整文本版本。Diff 在已展示统一缩进结果时搜索该版本，其余情况下搜索该侧原始文本。Worker 按字面扫描全文，使用与编辑器一致的 UTF-16 原文偏移，保证跨分段命中只统计一次。忽略大小写时仍使用原文的匹配范围。对高密度命中使用稀疏检查点及就近补扫，限制索引体积。界面接收计数、当前命中和可见片段所需的范围，高亮由当前文档版本决定。

### 导出与性能验收

下载从完整 `Blob` 生成，预览独立取片段。复制优先使用适用的剪贴板接口写入完整文本，支持时直接写入 `text/plain` Blob。浏览器拒绝写入时展示失败状态和下载入口。统一差异在 Worker 内生成，验收时应用到统一缩进后的左侧文档并逐字符校验右侧结果。

以打包后的 Chrome 和 Edge 扩展执行验收，记录浏览器版本、设备和测试步骤。1 MiB 和 10 MiB 的常规数据用于验证转换、完整导出、全文搜索和少量差异的对比。50 MiB、多处大范围差异、深层嵌套、超长单行和高密度命中用于验证资源预算，结果完整完成或清晰停止，输入持续可用。记录处理耗时、取消延迟、渲染主线程长任务和峰值内存，并单独检查滚动、输入和取消是否在 Worker 运行期间得到响应。按实测确定首版的切片大小和资源阈值。

## Risks / Trade-offs

- 格式化的缩进可能让输出远大于输入。生成结果时持续检查输出体积，并在达到预算时保留输入和错误状态。
- 传输大文本或安装完整编辑器状态也会造成主线程停顿。常规大文件路径传递文件引用和有界预览，压测另行覆盖大文本粘贴。
- 忽略大小写、分段扫描与 UTF-16 偏移容易造成遗漏或错位。用包含代理对、跨片段命中和重复命中的样本校验实际定位。
- 两份高度不相似的数据可能在预处理或对比阶段耗尽预算。分别限制输入、输出和算法工作量，整体超时由页面回收任务 Worker。
